# Content Contract v1

A content document should support:

- id
- title
- description
- type
- boardId
- classId
- subjectId
- chapterId
- topicId
- skillId
- language
- difficulty
- tags
- accessType
- status
- createdBy
- approvedBy
- createdAt
- updatedAt
- publishedAt
- scheduledAt

## Lifecycle

DRAFT → REVIEW → APPROVED → SCHEDULED → PUBLISHED

Alternative operational states:
PAUSED, ARCHIVED

## Rule

Educational content is data. It must not be embedded directly into learner UI source code.
